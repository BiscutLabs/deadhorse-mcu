# T30 Native QSPI read path

## Outcome

Done for scoped native-read RTL and focused acceptance: frozen checks and independent review pass; CI, production boot and physical qualification remain separate.

## What changed

- Added hw/ip/qspi_xip: optional native/read scheduler, extension register map,
  preparation, pin peer, interface scoreboards, formal harness and timing runner.
  Reuses the production T29 engine, shared input synchronizers and MMIO adapter.
- Added independent native performance permission, little-endian words,
  representable-address validation, captured CS1 command arbitration and idle-only
  keyed XIP configuration. Default T29 command-only behavior remains unchanged.
- Added opt-in native local-memory routing and full SoC binding. Instruction
  replies stay ordered; local data/DMA proceed during flash fetch. Client reset
  drains accepted flash/MMIO work and suppresses orphan replies; main-service
  reset cancels work. DMA stays SRAM-only and peripheral deadlines are unchanged.
- Added real two-core test firmware: recovery loads lite, lite enables XIP and
  releases performance, ROM jumps to flash code, which loads flash data and
  signals through GPIO. Added active-frame core-reset/restart checking.
- Extended the existing memory-control timing projection with an optional XIP
  emitter. The synchronous-memory audit and exact graph-restoration check are
  unchanged. Updated SoC metadata, contracts, focused runner and own tracking.

## Numbers

Register offsets, keys, permissions and modes are contract constants.
Estimated native bound: 2 × 53299 + 32 = 106630 running main edges, allowing
one maximum competing frame. This is not a proved liveness bound or physical
flash throughput measurement. The directed tests count main edges.

Measured by the frozen02 formal subcommands above: engine eight assertions
prove unbounded in 0.616 s; ineligible-owner two in 0.466 s; scheduler six in
0.466 s (ABC PDR). Engine/owner/scheduler BTOR covers take 4.270/0.415/0.366 s;
intended select/owner/endian faults take 0.416/0.416/0.315 s. These are measured
job wall times, not hardware performance. Only initial reset is assumed for
the scheduler; its requests/configuration/engine completion are arbitrary.
The unchanged T29 engine/owner stimulus restrictions remain explicitly listed
in their formal README. No safety proof is reported as a liveness proof.
