# T12 report

## Outcome

Done under the user's approved focused-verification scope: the standalone RV32F FPU passes T12 acceptance, the focused local gate and independent review; processor integration remains T13.

## What changed

- `hw/ip/fpu/`: clocked Chisel request/response FPU, registered transaction boundaries, cancellation, all RV32F operations, shared iterative arithmetic, formal monitors, tests and timing entry point.
- `hw/vendor/hardfloat/`: BSD-3-Clause sources pinned to `c1105e6ac6a0dd90fc80893efc4830ab609005d3`, byte-exact lock verification and five adaptation patches applied only under `build/`. The raw divider's internal interface now requires stable operands through its queued commit; the wrapper enforces this.
- `dv/fpu/`, `tools/env/fpu.lock.json`: pinned TestFloat/SoftFloat oracle, corner/random/vector tests, QEMU comparison, checker controls and a separate integer multiplication argument.
- `build.sbt`, `tools/sbt.py`, `tools/ci.py`: source preparation/build registration and explicit `--scope fpu` local gate. The default full gate retains every previous command and adds T12.
- FPU contract/verification notes, [formal ledger](../../../ledger/fpu-formal.md), the T12 row in the timing ledger, this report and the own status row.

The implementation shares fused arithmetic across ADD/SUB/MUL and all FMA forms, and final rounding across floating arithmetic and integer-to-float conversion. Multiplication consumes one significand bit per cycle; division/square root compute and commit one iteration over two clocks. Alignment, normalization, rounding and conversion stages are registered to meet GF180 timing. No operation, rounding mode, flag or subnormal behavior was removed.
