# T18 - Lite I2C recovery loader

## Outcome

Done. The lite I2C target accepts and verifies a recovery image, issues a start
request at its validated entry and retains the lock through external and lite-watchdog resets.

## What changed

The [contract](../../../spec/i2c-recovery-loader.md) defines the target wire
protocol, loader status, memory-completion boundary and clock/reset interfaces.
The block in `hw/ip/i2c_recovery_loader/` adopts the pinned clocked wire target,
loader command transitions, status bank and host/SRAM dispatch. The included
Apache-2.0 licence and provenance inventory identify the adapted inputs.
The ordinary controller and the programming lock use separately qualified
reset signals. External reset and lite watchdog invalidate the image and
cancel pending work. A previously set lock survives both. POR and brownout
clear both validity and lock.

Tests drive resolved I2C pins, use an independent CRC32 and memory peer, and
observe status, stored words and start requests. The acceptance driver binds
simulation, fresh production timing, formal checks and provenance. CI includes
the driver in both tiers.

## Deviations from the brief

Deadhorse follows the plan 12 reset policy as directed. A warm whole-chip
reset of a locked device leaves it in BOOT with PROGRAMMED clear and
PROGRAM_LOCKED set. Host reprogramming then requires POR or brownout.

## Open issues

Whole-chip integration must supply both qualified resets, flush the program
memory backend with the loader, and supply a qualified active service clock.
Whole-chip qualification still covers the AON wake catcher, CPU execution,
two-image boot, QSPI persistence, physical pins and clock startup. This task
ran the fast CI tier. The full tier belongs to later qualification.
