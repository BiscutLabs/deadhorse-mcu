# T42 lite boot-transfer latency

## Outcome

Done under D108's scoped/no-aggregate-CI policy: the production maximum-image
load passes the original 250 ms check without D104's bypass, with full readback
and unchanged clocks/capacity; inherited formal and physical debts remain below.

## What changed

- `LocalPermit.scala` replaces only production toAon's obsolete opposing-direction
  arbitration with a main-clock register, reset low by the existing qualified
  main reset. The debug leaf still uses DirectionPermit. BridgeSource/Target,
  FIFO, epochs, cancellation, memory and owner permissions are unchanged.
- `LocalPermitFormal.scala`, `local_permit_proof.py` and `local-permit.md` prove
  the actual primitive with faulty request, latency and reset controls.
- `BridgeSpec.scala` exercises old and local grants, exact-once downstream
  accounting, withdrawn offers, and actual wrong-data, lost-response,
  duplicate-response and stale-response-after-reset controls.
- `SocI1Spec.scala` reconciles two stale expectations with approved T41: service
  qualification is not an independent reset; shared warm reset flushes both
  mailbox endpoints; warm boot status is held plus fresh-warm (9), cold is held
  (1). Retained RAM, byte lanes, denied/forged owners, protected writes and
  release assertions remain. Fresh-mailbox and cold retained-image checks added.
- Boot `sim.cpp` adds real reset-pin interruption during copy and readback.
  Before a valid context commit, warm ROM must fail closed, with lite held and
  its client disabled; it must not boot an incomplete image.
- The load runner always requires the original budget without D104.
  `wire_campaign.py --t42` explicitly selects relevant cases and records unrun
  cases; default full campaign remains available. The passive analyzer checks
  every accepted effect across the full program aperture, including gaps.
- Added authenticated equal-library isolated area comparison; updated D108,
  D104 closure, area budget, ledgers, bridge documentation and STATUS.
