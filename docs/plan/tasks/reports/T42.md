# T42 lite boot-transfer latency

## Outcome

Blocked before hardware implementation pending approval of the independently
reviewed local-permit proposal; the measured baseline still exceeds the original
250 ms maximum-image target under D104.

## What changed

- Merged reviewed T40 `616b573` to main and pushed merge `f680c3f`.
- Added passive timing ports to the test-only `SocBootRomProbe` and optional
  `dv/soc/boot/transfer_trace.hpp` observation in the existing pin-level peer.
  Production RTL, firmware, assertions, limits, clocks and memory are unchanged.
- Added `dv/soc/boot/load_profile.py` for the two relevant production image-load
  cases, source/artifact hashes and measured command times; `analyze_load.py`
  validates every write/read against independent flash bytes and reports stages.
- Wrote [the concrete proposal](../../../spec/t42-lite-transfer-proposal.md):
  replace only production toAon's obsolete direction arbitration with a
  main-clock registered permit. Leave the bridge and shared CDC/reset machinery.

Baseline02 measured subprocess walls: input preparation 3.819861 s, fixture
compilation 0.966113 s, Chisel emission 13.484163 s, Verilator build 9.729766 s,
watcher simulation 8.777196 s and maximum-image simulation 14.847858 s. This is
not a claim about aggregate CI time. Original full boot, formal and unrelated IP
suites were not run for this passive investigation.

Independent agent review checked the passive taps and sampling, authenticated
trace/flash receipts, full word inventory, estimate arithmetic and proposed
grant scope. Both analyzer findings (fixture metadata authentication and exact
withdrawal association) were fixed and verified with trace controls, requiring
no simulation rerun. The final analyzer has its own hash in analysis03; its
post-baseline edits and report/tracker edits do not change the frozen simulated
RTL, firmware or C++ observer. No production behavior change was reviewed or
accepted because implementation is not yet authorized.
Final independent review accepted publication of this investigation/proposal
only, with no remaining findings; it did not run tests or claim hardware closure.

The readback attribution fix only decodes actually retired RV32IMFC memory
instructions before using their RVFI fields. It does not alter the core or
turn unused fields into new architectural assertions. Analysis fails closed
on an incomplete/overlapping stage sequence, missing/duplicate retirement,
wrong address or data. Its internal source-address labels are valid only for
the held-lite serial cases and do not prove concurrent-master transport.
