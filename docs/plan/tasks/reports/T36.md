# T36 Production boot ROM firmware

## Outcome

Done under the approved scoped policy and D104 maximum-image latency
exception; frozen Phase3 fast passes with inherited proof deferrals.

## What changed

- One performance ROM: paired A/B/golden selection, CRC/bounds/compatibility,
  SRAM and held-lite copy/readback, optional release, retained same-generation
  watchdog restart, stackless DMA/QSPI drain, UART recovery and commit-last
  updates. No lite ROM, I2C recovery or cross-core boot handshake.
- Boot-control cold-epoch/context metadata with keyed commit, stale-hold
  protection, unchanged ownership checks, independent tests and formal faults.
- Production preparation/emission bind the actual ROM. Mapping authenticates
  every initialized word and retains ROM in the whole-SoC synthesis. Isolated
  ROM area is nonadditive. Budget/leakage scripts include actual firmware.
- Native and production NOR/UART wire tests, exact copy/update oracles, stack
  and reset observations, finite IMFC/mailbox smoke. No injected bus master.
- Fixed unsupported user-cycle CSR reads using machine mcycle, preserving
  timeouts. CRC lookup retains the polynomial and complete RAM readback.
  Fixed recovery RX overflow with bounded service after immutable request
  capture and between flash commands; nested requests return BUSY.
- D104/T42 record temporary maximum-image latency acceptance and a follow-up.
  T41 reset consolidation is separately queued, not implemented here.
