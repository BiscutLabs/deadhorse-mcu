# T36 Production boot ROM firmware

## Outcome

Blocked before implementation on the explicit boot-path, ownership and recovery
decisions required by the T36 brief; a concrete proposal is prepared for approval.

## What changed

- D91 records the user's same-policy direction: relevant tests only, no CI,
  defer extensive proof timeouts, preserve independent review and stop conditions.
- [Boot proposal](../../../spec/boot-rom-proposal.md) enumerates the existing
  reset instruction source, program loading, release and lock behavior; proposes
  the narrow ROM/start binding, protected-program copy/seal, real loader handoff,
  performance-ROM UART recovery and paired-image policy.
- STATUS records this prerequisite. No RTL, firmware, map or test changes.

Independent proposal review confirmed the prerequisite and requested explicit
two-core readiness/commit and preservation of live DMA buffers after a
performance-only reset. Both are now in the proposal. This is review of a
proposed contract, not approval to implement its new authorities. No simulation,
formal job, timing run, fast CI or full CI has run for T36. The boot campaign
does not yet exist and is not passed or waived.

## Numbers

No new hardware or performance measurements. Existing contract constants:
16 KiB performance SRAM, 2048-byte lite program and 1024-byte working RAM,
64 KiB existing main ROM aperture. The aperture is not measured physical ROM
capacity. The proposed NOR geometry and new boot policy remain proposals.

## Deviations from the brief

D91 replaces aggregate CI/unrelated tests and extensive proof timeout work
with scoped checks and explicit deferrals. No other requirement is changed.
The brief explicitly requires a reviewed boot feasibility contract before RTL
and a stop for new mapping/ownership/image policy; this is that prerequisite.

## Open issues

Approve or revise the proposal before implementation. In particular, trusted
ROM needs new program-write authority and a real recovery ownership handoff;
firmware UART recovery needs an explicit capability profile instead of claiming
gateway-origin access. All T36 implementation and acceptance remain unverified.
