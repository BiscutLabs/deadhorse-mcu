# T41 reset consolidation

## Outcome

Done within T41's scoped verification policy: production reset consolidation, paired-image warm boot and mapped setup/area checks pass, with the explicitly permitted proof deferrals and physical signoff obligations retained below.

Independent agent review accepted the implementation, revised test obligations,
measurement attribution and final evidence qualifications. The final publication

qualification scripts/helpers and the corrected receipts. No merge to main.

## What changed

- `SocResetDomains`, `SocClockedTop`, `DeadhorseSoc` and `SocI1Peripherals`
  bind shared cold/warm releases. Both watchdogs reset ordinary services and
  cores together; debug/causes survive warm; SRAM contents are never reset-cleared.
- `OscSourceControl`, oscillator policy and bootstrap replace private reset
  epochs with acknowledged clearing. Pin pulses inside held warm reset and
  reset during OFF/STARTING force fresh qualification. USB retains its own
  prior cold/pin qualification behavior.
- Shared CDC/RegBlock options provide synchronous initialization where needed;
  unchanged default modes remain available. D106/D107 retain asynchronous
  DMI/bridge quarantine and selective BIST pin abort, followed by acknowledged
  flushing. These decisions were committed before consolidation.
- Lite core/adapter initialization acknowledges complete state clearing before
  program-RAM writes become legal. Boot-control hold/start state is warm-owned;
  selected-bundle context is cold-owned. Reset causes include debug in the
  existing cause ABI, passed to the application in `a3`.
- Warm ROM validates both retained images, skips both copies only when both
  CRCs match, otherwise reloads the pair, and keeps lite held until confirmation.
  Invalid retained context stays fail-closed until genuine cold reset.
- `soc.yaml`, reset/boot specifications and the before/after inventory describe
  the implemented four cohorts and explicit cancellation exceptions. Relevant
  tests replace retired cohort expectations; none is silently removed.
- Measurement tools authenticate current USB/counter islands, generated-clock
  anchors and frozen AON mux modes. The counter timing fix removes only an
  unused synchronous count clear, with output-cycle equivalence checked.

## Deviations from the brief

The required inventory commit precedes RTL. D106/D107 now explicitly authorize immediate DMI/BusBridge cancellation and
selective BIST pin-abort capture beyond cold/warm source handling.
A purely synchronized abort changes the no-late-dispatch contract. The diagnostic does not substitute for implementation acceptance. Existing
service qualification is identified as initial readiness, not a reset source
that can simply be deleted. Cold-owned controller state must be able to restart
and qualify clocks while debug holds application warm reset.

## Open issues

Broad lite initialization and SRAM ownership proofs remain deferred at their
unchanged 120-second caps. T33's full shutdown/startup composition is still
unproved: local clear/ack, reset and cadence proofs do not establish the whole
composition. Physical hold/RDC/reset-removal obligations remain open as above.
The default DMI transport theorem uses local two-edge main-clock reset release.
Production now receives coldMain from the ungated divided clock while DMI runs
on gated main. Release/ready latency can differ, so the local theorem is not a
proof of that qualified production composition. That composition remains
deferred, supported by real-JTAG ndmreset and production reset-phase simulations;
no structural-equivalence or whole-DMI proof claim is made.
