# T25 Clocked lite core and AON binding

## Outcome

Blocked on complete architectural formal qualification; the clocked lite-core
RTL, machine-mode extension and opt-in recovery-loaded AON binding are implemented.

## What changed

- `hw/ip/lite_core`: pinned RISCay clocked baseline/shared ISA and independent
  software oracle, license/blob provenance, registered single-credit LocalBus
  adapter, machine CSR/trap/interrupt/WFI hart and RVFI outputs.
- `SocI1Peripherals.scala`, `SocI1Config`, `EmitSocLite.scala`: opt-in real
  lite master on the existing AON fabric/reset cohort. Loader START validates
  programmed/quiescent/halted/aligned/in-range conditions and adds the global
  SRAM base to the entry offset. Hardware owns origin and halted status; old
  stand-in inputs are inert. IRQ and clock demand are connected.
- `dv/soc/lite_recovery.S`, preparation and focused checking scripts: an
  RV32E/Zicsr image linked at retained SRAM, entered at a nonzero offset through
  actual recovery I2C wires. Firmware uses working SRAM, timer and mailbox IRQs,
  MRET/WFI. Main reset preserves execution; AON reset cancels it and retains SRAM.
- Core/bus/machine/integration tests compare public behavior with independent
  architectural/bus expectations and retain actual RTL fault controls.
- Formal sources qualify faithful adoption, adapter and control safety;
  pinned riscv-formal instruction-model checks remain separately classified.

Independent review found and resolved a loader START status race: on the
handoff edge, the old core halted value could overwrite RUN with HALTED.
The real-hart binding suppresses only that handoff status; memory ownership
uses actual halted. A public loader-wire RUN check and restored-defect negative
exercise it. Review also found inconsistent RVFI byte-address/lane convention;
the port now uses aligned addresses and physical masks, with all byte offsets
and the upper halfword exercised.
