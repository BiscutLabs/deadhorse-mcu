# S3 memory measurement report

## Outcome

Done: S3 measurement acceptance, independent review and the fast CI tier passed;
the four inherited T14 proof deferrals remain unproved, and the full tier was not run.

Both representative hard-float builds stay below the unchanged 12 KiB review
threshold. Estimated performance working sets are **10,176 bytes (`-Os`)** and
**10,616 bytes (`-O2`)**, including reserved stack and 2,304 bytes of logging
storage. These are fixture allocation estimates, not complete flight firmware
or placed SRAM qualification. No capacity increase or footprint optimization
was performed.

## Numbers

Compiler **GCC 13.2.0**, pinned QEMU package from `dv/core/iss.json`;
main uses RV32IMFC plus Zicsr / `ilp32f`, lite RV32E plus Zicsr / `ilp32e`.
Both size and speed profiles use function/data sections, section GC, stack
records and the same fixture controls. Hardware F remains enabled in both main
builds. QEMU execution is not a Deadhorse cycle or peripheral-timing measurement.

Code, constants, data and observed SP below are **measured** by the aggregate.
Reserved stack and candidate allocation are **estimates** from those inputs:
`hot code + conservative hot constants + candidate mutable bytes + reserved stack`.
The stack estimate adds the deepest hot call chain, one full trap/handler and
live `main`; the larger observed peak is retained. No nested traps are assumed.

| Main `-Os` | 4828 | 3092 | 964 | 3696 | 448 | 688 | 10176 |
| Main `-O2` | 5324 | 3568 | 964 | 3688 | 448 | 640 | 10616 |

The **8192-byte cold BMI270 configuration** is separate from that table.
Bosch API v2.113.0 is pinned to
`41129fcfe39c583ee5462d79195741945d51c1fe`; six unchanged upstream files are
hash-verified. The actual payload hash is
`2d75e68e343a13ff99be98261dfbd99d9e8c6f267da9e3c5aeb883276ad178db`.
The driver uploads **128 measured chunks of 64 bytes**, enables accel/gyro and
reads through the real parsing path. A separately reported **152-byte sensor
model** is excluded from candidate mutable RAM. Model and observer *code* remain
conservatively included in the hot closure. The actual SPI HAL is still absent.

Estimated baseline headroom is `16384 - 10176 = 6208 B` at `-Os` and
`16384 - 10616 = 5768 B` at `-O2`. Lite subset headroom is 2424/2408 B.
Hot code sums function symbol sizes; final placement/alignment is not performed.
Remaining text includes cold code, startup and linker padding. These figures
must not be presented as final firmware-fit guarantees.

**SRAM model:** measured 17,406 transactions, 18 combinations of capacity/banks/
assumed latency, all 16 byte masks, boundaries, invalid addresses and response
backpressure. Bank aliasing, swapped lanes, disabled-byte overwrite and early
completion are rejected. Latencies of 1/2/5 edges are assumptions, not macro results.

**Flash model:** commands and phase widths are explicit in the receipt and
`dv/memory/README.md`: assumed serial 12 MHz fast read `0x0c`, or quad 24 MHz
`0xec` read; four-byte addresses; serial `0x12` page program, `0x06` write enable
and `0xdc` erase. Page/burst limit is 256 bytes. Maximum busy waits of 3 ms for
program and 400 ms for erase are **assumed**, with no status-poll traffic. The
logging chip releases the bus during busy time; it has a separate chip select.

| Assumed profile | Estimated 64-byte XIP response bound | Model worst response | Measured model logging result |
| --- | --- | --- | --- |
| Serial, 12 MHz | `(2090 + 562) / 12 MHz = 221 us` | 2652 SCLK edges | 38,400,000 B committed; no dropped records |
| Quad read, 24 MHz | `(2090 + 154) / 24 MHz = 93.5 us` | 2244 SCLK edges | 38,400,000 B committed; no dropped records |

Each profile checks every arrival edge during WREN/program/erase. The logging
scenario supplies 64 bytes at 1 kHz for 600 seconds, batches four records per
page, uses a pre-erased region and **one 64-byte XIP read per second**. A final
one-second drain is allowed; the last page becomes durable at modeled
600.002175 s / 600.0020875 s. Continuous priority XIP can starve logging; this
is not an unconditional throughput guarantee. Erase-during-flight stress drops
and counts **372 records** without blocking the producer. Missing dummy clocks,
unbounded bursts and holding the bus during array busy are rejected.

Storage arithmetic is **estimated**: `64 * 1000 * 600 = 38,400,000 B` versus
`40 * 2^20 = 41,943,040 B`, leaving 3,543,040 B before metadata/reserves.
No flash part, QSPI clock derivation or UART assignment is selected.

**Physical:** no new area, timing or power measurement. Inherited planning
footprints give estimates `16 * 155414 um2 = 2.486624 mm2` main and
`3 * 155414 um2 = 0.466242 mm2` lite, excluding wrappers/routing. Macro access
latency, banking overhead, retention and power remain unqualified.

## Deviations from the brief

No new hardware block is introduced: banking and arbitration are executable
organization models. Firmware runs in QEMU DRAM; SRAM/XIP placement is analyzed,
not implemented. An ecall exercises real save/restore storage, not asynchronous
interrupt arrival or pin latency. The lite image measures a documented
CRC/chunk/wake/calibration subset, not the complete loader.

Routine fixes retain failed evidence: Bosch's unused stdio include is satisfied
by a measurement-only compatibility header without vendor edits. Initial hot
call accounting missed calls after local objdump labels; its diagnostic receipt
is superseded by section-aware ownership and linked-call coverage. GCC IPA clone
names require conservatively matching stack records; missing evidence fails.
`build/s3-firmware-01/02/` are not accepted footprint evidence. No failed limit
was relaxed and no workload was optimized to force a fit.

## Open issues

- Complete drivers, real SPI/DMA/scheduler code, navigation and retained boot
  recovery may consume the estimated headroom. Final hot placement and static
  cold-init/error-path stack bounds remain to be established.
- Select and qualify flash commands, worst busy times, clock rates, metadata and
  erase policy on real parts. Bound actual XIP demand before asserting sustained
  logging; the tested cadence is explicitly limited.
- Select/characterize SRAM macros and integrate actual RTL; no one-cycle access,
  power reduction or physical memory-fit claim follows from this study.
- T13's prior unresolved formal acceptance and T14's four explicit proof
  deferrals remain unchanged. This task does not close those obligations.
