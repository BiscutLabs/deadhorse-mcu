## Outcome

Done: the initial contract/map milestone; T20's connected RTL, firmware tests,
formal/timing measurements and overall acceptance remain incomplete.

## What changed

- `docs/spec/soc.md`: I0/I1 boundary, local memory path, region subdivision,
  origins, retained-memory permissions, reset matrix/readiness, bridge bounds,
  loader binding, interrupts, stub semantics, clock limits and inherited issues.
- `hw/top/reference/soc.yaml`: provisional configuration; generated outputs are
  under `build/t20/map/`, not tracked.
- `hw/top/reference/check_soc_map.py` and `test_soc_map.py`: strict description
  validation, existing register-map reuse, spec-table comparison, configuration
  output and negative controls. This is not a synthesized SoC address decoder.
- Reference README and own STATUS row/log. User-directed workflow uses `main`
  directly; prior USB/S1 and SoC plan work was fast-forwarded and pushed first.

## Numbers

The map check above **measured** nineteen configured region descriptions;
the focused unit command **measured** seven passing test methods, including
configuration fault controls. These are tooling results, not hardware results.
Clock frequencies, model latency, address subdivisions and logical pin groups
are **assumed provisional configuration**. SRAM capacities are existing
requirements. Estimated SPI limits and their arithmetic are in the contract.
No new SoC area, timing, instruction count or physical fit is claimed.

## Deviations from the brief

None accepted. The brief's required gateway-based target interface has no
production gateway RTL to bind today. The user has been asked whether to use
an explicitly simulation-only adapter or expand production gateway scope;
neither choice has been assumed. Independent map work proceeds without it.
The initial map does not yet encode fabric hierarchy or complete pin allocation.
