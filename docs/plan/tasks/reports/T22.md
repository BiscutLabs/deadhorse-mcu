# T22 General-purpose PWM

## Outcome

Done for the functional T22 PWM implementation and independently reviewed frozen checks; CI, DMA-controller integration and physical qualification remain open.

## What changed

- Added `hw/ip/pwm`: nine independent clocked PWM channels, generated register
  map, queued configuration snapshots, ordinary output disable, event IRQ and
  acknowledged DMA request/overrun interface. No application protocol or policy.
- Added `SocPwmFiles`/`EmitSocPwm`, replacing the reserved output stub only in
  the new profile. Existing window, pins and IRQ10 are retained; clock demand
  is connected. Validated map metadata defines main-service reset and the
  low 256-byte decode. Existing I1 and T21 profiles are unchanged.
- Added duration-model tests, MMIO/DMA tests, real-core reset firmware/test,
  scoped formal harnesses and frozen verification runners. Updated block/top
  contracts, bus/SoC spec, task tracker and timing/formal ledgers.

## Deviations from the brief

No functional or acceptance deviation. The timeout used the first authorized
triage rung only. Existing generic reset policy allowed the new main-service
reset contract; the prior inactive profiles retain their behavior.

## Open issues

- DMA requests are implemented, but the DMA controller and memory transfers
  are not. The SoC ties the external acknowledgement low; software can clear it.
- Exact waveform timing is duration-model simulation evidence; formal results
  are safety/update claims, not elapsed-time progress or whole-SoC proofs.
- The real-core reset test verifies active/queued waveform preservation while
  reset is held. It does not qualify a firmware reboot/reconfiguration sequence.
- Physical pad, hold/RDC and routed timing remain open, along with inherited
  T19/T20/T21 qualification items. Both CI tiers are unrun.
- Changes remain local on main alongside uncommitted T20/T21 dependencies;
  this task does not commit an incomplete or unrelated dependency set.
