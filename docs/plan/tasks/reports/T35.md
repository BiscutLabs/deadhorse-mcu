# T35 SRAM macros and memory self-test

## Outcome

Done under D90's scoped acceptance: production SRAM/BIST and relevant tests
pass, with two formal proofs deferred and physical signoff still open.

## What changed

- `hw/vendor/gf180_sram/`: Apache-2.0 macro lock and exact Git-blob extraction
  for twenty 1024x8 instances, five timing corners, layout and specification views.
- `hw/ip/sram/`: little-endian byte/word wrapper, independent simulation memory,
  March C- agents, reset-held ownership and custom DMI registers at 0x70–0x7f.
- Production local/retained memory, reset/clock demand and debug DMI bindings;
  `soc.yaml`, map checker, production preparation and the SRAM physical contract.
  Logical 16 KiB/3 KiB capacity, normal MMIO maps, banking and latency remain intact.
- `dv/soc/sram/`, Scala tests and formal harnesses: array/mask/operation oracles,
  fault injection, reset/ownership and production TAP checks. Existing tests stay.
- Production timing supports real macro Liberty interfaces and verified load
  buffering; the area budget uses actual standard cells plus LEF footprints.
- D90, plan08, the memory ledger and formal README retain verification and
  physical qualifications. No new peripheral, ROM replacement or USB RAM swap.

## Deviations from the brief

D90 replaces aggregate CI and extensive proof timeout work with relevant tests
and explicit deferrals. It does not waive physical signoff, change limits,
assertions or normal behavior. Independent review corrected a newly written
ownership assertion that confused delayed admission ACK with actual reset hold;
`ownership03` retains that counterexample. `ownership01/02` are tool-lowering
and hierarchical fault-name parsing failures. Functional logic was unchanged.

No new SRAM organization is selected: all twenty planned byte macros are used,
with retained rows 768–1023 inaccessible. The vendor's operating/standby
specifications support always-powered normal-rail sleep; they are upstream
evidence, not characterization performed here. Metadata/truth-table
inconsistencies remain explicit in the physical handoff.

## Open issues

- The two timeout proofs and broader bank/latency/mux/CDC/RDC composition remain
  unproved. Existing T13–T34 debt is unchanged.
- Physical CTS, extracted setup/hold/pulse checks, rail/IR-drop/POR margins,
  view reconciliation, macro placement, DRC/LVS and scan integration remain
  T37/T38/signoff dependencies. No low-voltage or power-off retention claim.
- BIST is destructive. Reload both memories before executing retained code;
  the existing loader lock remains cold-reset-owned. A stopped AON clock holds
  the system reset until completion or a common cold/pin abort.
- T36 still supplies production ROM firmware. No integration-stage exit or
  tape-out gate is closed by this scoped result.
