# T17: I2C controller

## Outcome

Done: the standalone I2C controller passes acceptance and fast CI, with eight
formal jobs explicitly deferred/unproved under the existing continuation direction.

## What changed

- T17 brief, task index and `docs/spec/i2c-host.md`: reviewed byte-command
  controller contract for START/restart, WRITE, READ with ACK/NACK, STOP and
  explicit bus recovery; ownership, timeout, register and sleep semantics.
- `hw/ip/i2c_host/`: generated registers, clocked Chisel controller, shared
  pin synchronization plus digital stability filtering, public-wire tests,
  scoped formal harnesses and real fault controls, aggregate acceptance.
- `build.sbt`, CI tier registration and receipt tests; I2C formal/timing ledgers
  and own STATUS row/log. Prior S1/T13 changes remain separate.

Firmware sequences bytes into transactions. No I2C DMA/FIFO, target/loader,
sensor firmware or SoC wiring is added. RISCay's separate loader is untouched.
The first timing result exposed a protocol-completion mux ahead of a 16-bit
watchdog decrement. Split byte counters preserve its exact arithmetic and
deadline priority while removing that long path; no limit or behavior changed.
Review also found a missing continuous SDA contention check during repeated
START setup. The scoped repair enforces the existing guard contract; a public
wire regression verifies an early dip cannot be ignored until the guard ends.
Formal runner review additionally required the actual solver timeout exit code
before accepting a TIMEOUT status. Behavioral tests first reproduced the gap
with six malformed exit codes, then passed after the repair; evidence remains
at `build/t17/fresh-timeout-before.txt`. No property or limit changed.
Review also reproduced a clean-checkout portability issue: Git's LF/CRLF
conversion changed the environment-lock hash despite identical content.
Environment identity now uses a documented CRLF normalization, preserving all
reviewed historical identities while binding every other byte. Model and
artifact hashes remain raw. The regression preserves failure evidence at
`build/t17/environment-line-ending-before.json`.

## Open issues

- Eight I2C formal jobs remain unproved, including two actual-fault controls;
  passing simulation does not turn these timeouts into formal results.
- Digital tests/formal do not qualify pull-ups, rise/fall, pad hysteresis,
  board load, oscillator tolerance, metastability/MTBF or physical reset/clock
  distribution. Rate figures derive from measured cycles and assumed HF clocks.
- Single-controller sensor-bus scope; contention detection is not complete
  multi-controller interoperability. Stuck SCL or persistent stuck SDA can
  require external target reset/power cycling after reported timeout.
- TIMEOUT is a configurable controller policy, not a standard I2C stretch
  limit. Firmware must choose it for the sensor and command-service latency;
  timed-out writes may already have had target-side effects.
- Ownership transfer, HF startup/gating, pin mux, sensor firmware and the
  retained recovery loader remain later integration/adoption briefs.
- T13/S1 and inherited T14 deferrals remain open; no gate is checked.
