# Flight-loop instruction-count measurement

The evidence behind requirement R-CPU-1 in
[docs/plan/02-requirements.md](../../../docs/plan/02-requirements.md): how many
RISC-V instructions one iteration of the Stallion VTOL inner control loop
costs.

## Reproduce

```sh
./run_all.sh
```

Needs `riscv64-unknown-elf-gcc` with rv32 multilib (measured with 13.2.0),
`gcc`, `python3`. The QEMU cross-check runs only if `qemu-system-riscv32` is
installed. Takes under a minute. Output goes to `build/` (ignored) and
`results/`.

Verified 2026-11-13: a rerun from a clean copy reproduced `results/summary.md`
and `results/summary.json` byte for byte.

## Headline numbers (RV32IM, `-O2`, fixed point)

| Mode | Mean | Worst observed |
| --- | ---: | ---: |
| Hover | 1,737 | 1,804 |
| Fixed-wing | 1,768 | 1,774 |
| Mid-transition | 2,101 | 2,171 |

## Known limits

- The loop content is our design, not a flown autopilot. It assumes two
  ailerons, one elevator and one rudder. See `REPORT.md`.
- Counts are instructions, not cycles.
- **The QEMU cross-check is fragile by one instruction.** It derives the
  count from a trace log and its end-of-program detection depends on where
  the log is cut. One run matched all four configurations exactly; a rerun
  matched one and was off by one instruction (in 0.3 to 6.3 million) on the
  other three. The simulator's own counts are deterministic.
- `src/params_gen.inc` is generated by `scenario/gen_params.py` and is
  rewritten on every run.
