# Flight-loop instruction-count measurement

The evidence behind requirement R-CPU-1 in
[docs/plan/02-requirements.md](../../../docs/plan/02-requirements.md): how many
RISC-V instructions one iteration of the Stallion VTOL inner control loop
costs.

## Reproduce

```sh
./run_all.sh
./check.sh
```

Needs `riscv64-unknown-elf-gcc` with rv32 multilib (measured with 13.2.0),
`gcc`, `python3` and `qemu-system-riscv32`; missing tools fail the check.
Run through the pinned Linux image:
`python tools/env/run.py run -- bash sw/flight/loop-measurement/check.sh`
from the repository root. This check is also required by `tools/ci.py`.
The local `.gitattributes` keeps shell scripts LF on Windows; an existing CRLF
checkout must be normalized before direct execution.

Binaries, traces, generated includes and supporting logs go under ignored
`build/`. Historical summary files and the QEMU comparison remain in `results/`.
`check.sh` requires the summary to match the committed bytes and requires every
expected QEMU configuration to have identical counts, with no tolerance.

Verified 2026-11-13: a rerun from a clean copy reproduced `results/summary.md`
and `results/summary.json` byte for byte.

## Known limits

- The loop content is our design, not a flown autopilot. It assumes two
  ailerons, one elevator and one rudder. See `REPORT.md`.
- Counts are instructions, not cycles.
- QEMU counting uses `sim_finish` and `sim_spin` from the ELF symbol table.
  The exit store counts; the terminal loop does not. The collector stops on
  the first spin record, or accepts a successful QEMU finisher exit whose
  last instruction is the named exit store. Missing markers, truncated traces,
  failed exits and the unchanged timeout all fail. MMIO re-entry duplicates are
  collapsed; this workload has no legitimate consecutive same-PC instructions
  before its terminal spin. This is not a general trace decoder.
- `build/params_gen.inc` is generated by the unchanged `scenario/gen_params.py`.
  No generated include is stored in `src/`.
- The measurements remain historical: the elevator/rudder workload is not the
  approved V-tail firmware and does not establish full-F MCU performance.
